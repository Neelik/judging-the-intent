# judging-the-intent

## Setup

The easiest way to run the scripts is by using [`uv`](https://docs.astral.sh/uv/). After `uv` has been installed, clone the repository and create a virtual environment:

```bash
uv sync
```

> [!NOTE] 
> This repository is database-driven, and was designed using postgresql. To install and configure Postgres, refer
to their documentation: [PostgreSQL Docs](https://www.postgresql.org/docs/).

## Usage

The scripts expect the following environment variables to be set:

- `POSTGRES_DB`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_HOST`
- `POSTGRES_PORT`
- `HF_ACCESS_TOKEN`

*NOTE* The `HF_ACCESS_TOKEN` is a token required to access gated repos on HuggingFace. This is 
configured on your [HuggingFace Profile](https://huggingface.co/settings/tokens).

Additional optional environment variables can be set:

- `UV_ENV_FILE` - Defines the path to the .env file you wish to be used by the `uv run` command.
- `IR_DATASETS_HOME` - Define path to the cache directory for the `ir_datasets` package to download datasets.
- `CACHE_DIR` - Path to a cache directory for HuggingFace models

### Database Preparation

First, run `create_db` in order to create initialize the database schema with the necessary tables.

Second, run `load_db`, found in the `db` directory, to load datasets into the database, for example:

```bash
uv run python -m src.judging_the_intent.util.load_db --datasets corpus-subsamples/clueweb09/en/trec-web-2010 corpus-subsamples/clueweb09/en/trec-web-2011 --data_dir datasets/
```

*NOTE* The datasets argument takes in strings that match available datasets from the [ir_datasets](https://ir-datasets.com/index.html) 
Python package, or their subsampling.

### Annotation - LLM

Annotation can be performed using any pretrained HuggingFace model that can be loaded as a `AutoModelForCausalLM` and its
related Tokenizer. Additionally, if you have a saved checkpoint for a fine-tuned PEFT adapter, this can be loaded. The 
easiest way to begin an annotation run is to specify the model and prompt style:

```bash
uv run python -m src.judging_the_intent.annotate --model meta-llama/Meta-Llama-3-8B --prompt_style binary
```

*REMINDER* Some models have gated access on HuggingFace. To gain access to these models, you must request access from
the model owner on HuggingFace, and add the appropriate permissions to your access token. Model loading will fail if
permission is not granted.

#### Command Line Arguments for `annotate`

- `--model` - HuggingFace model identifier for an AutoModelForCausalLM class to be loaded.
- `--datasets` - Dataset identifiers if you wish to limit the annotation to a specific dataset. If not provided, all unannotated items will be annotated.
- `--prompt_style` - Defines the style of prompt to be utilized in the annotation run. More details can be found in [Prompt Styles](#prompt-styles).
- `--checkpoint_path` - Path to saved PEFT checkpoint. If provided, the script will attempt to load a PEFT model using the original model as the base.
- `--batch_size` - Defines the number of annotations to perform in a single batch. Default value is 16.
- `--max_input_length` - Defines the maximum tensor size for a single tokenized prompt. Default value is 2048.
- `--max_doc_length` - Defines the maximum number of characters to extract from a document for use in the prompt. Default value is 1400.
- `--intent_source` - Define whether the Intents related to the Triples originate from humans, i.e., those produced for TREC, or are generated by an LLM.

### Annotation - Human

The annotate script also supports loading original QRels as human annotations, allowing for fully database-driven behavior. To load original Qrels,
pass "human" to the `model` and `prompt_style` arguments:

```bash
uv run python -m src.judging_the_intent.annotate --model human --prompt_style human --datasets corpus-subsamples/clueweb09/en/trec-web-2011
```

To load intent-aware human annotations, be sure to set the `intent_aware` flag and pass "human-intent" as the `prompt_style`.

### Evaluation

Evaluation of the annotations is performed with the `evaluate` script. As with the annotation, there are a number of command line arguments available for fine-grained
control. The simples evaluation can be done as follows:

```bash
uv run python -m src.judging_the_intent.evaluate --model meta-llama/Meta-Llama-3-8B --datasets corpus-subsamples/clueweb09/en/trec-web-2011 --prompt_style binary
```

#### Additional Command Line Arguments for `evaluate`

- `--model` - HuggingFace model identifier for the model used in the annotation run
- `--datasets` - Dataset identifiers for the dataset annotations to be retrieved
- `--qrels_true_path` - File path to a ground truth qrels file if you prefer to evaluate file-based instead of from the database
- `--intent_aware` - Flat to indicate whether the evaluation is to consider intent-aware annotations
- `--checkpointed_model` - Flag to indicate whether the annotation was performed with a checkpoint loaded
- `--prompt_style` - Defines the style of prompt utilized in the annotation run. More details can be found in [Annotation Prompt Styles](#annotation-prompt-styles).
- `--intent_source` - Define whether the Intents related to the Triples originated from humans, i.e., those produced for TREC, or were generated by an LLM.

### Annotation Prompt Styles

#### binary

A simple prompt construct sourced from [QPP-GenRE](https://github.com/ChuanMeng/QPP-GenRE/tree/main) that instructs the model to give judgment of relevant or not relevant.

```text
Instruction: Please assess the relevance of the provided passage to the following question. Please output "Relevant" or "Irrelevant".
Question: {question}
Passage: {passage}
Output:
```

#### binary-intent

Modified version of the binary prompt to include the intent.

```text
Instruction: Please assess the relevance of the provided passage to the following question. Please output "Relevant" or "Irrelevant".
Question: {question}
Intent: {intent}
Passage: {passage}
Output:
```

#### dna

Description, narrative, and aspect prompt style inspired by that introduced in [Thomas et al.](https://dl.acm.org/doi/pdf/10.1145/3626772.3657707)

```text
You are a search quality rater evaluating the relevance of web pages.
Given the user query, and a web page, you must provide a score on an integer scale of 0 to 4 to indicate to what extent the given document meets the information needs of the user.
The scores have the following meanings:

0: fails to meet
1: slightly meets
2: moderately meets
3: highly meets
4: fully meets

Query: {question}
Passage: {passage}
Score:
```

#### dna-intent

Modified version of the dna prompt to include the intent. 

```text
You are a search quality rater evaluating the relevance of web pages.
Given the query of the user, user search intent, and a web page, you must provide a score on an integer scale of 0 to 4 to indicate to what extent the given document meets the information needs of the user.
The scores have the following meanings:

0: fails to meet
1: slightly meets
2: moderately meets
3: highly meets
4: fully meets

Query: {question}
Intent: {intent}
Passage: {passage}
Score:
```

### Generating Search Intents

This repository also supplies scripts to generate new intents for a dataset, based on queries and 3 random judged documents for that query.
To generate intents:

```bash
uv run python -m src.judging_the_intent.generate_intents --dataset corpus-subsamples/clueweb09/en/trec-web-2011
```

As with `annotate`, you can also specify a HuggingFace model of your choice. By default, the `meta-llama/Llama-3.1-8B-Instruct` is used.

> [!NOTE] 
> This script runs exclusively off the underlying database. Intents can only be generated for datasets already loaded.

### Intent Generation Prompt

For transparency, the prompt used in the generation of intents is provided here. This prompt is inspired by that used in [Anand et al.](https://dl.acm.org/doi/pdf/10.1145/3627673.3679166)

```text
A person wants to determine distinct intentions behind a query.
 
Query: {query}.

Give five descriptive (max. 15 words) distinct intentions which are easy to understand. Consider all documents in your response. 
Response should be in the format: Intentions:: <intention>, Document_List:: <list of documents with the intention>.

Documents: {documents}
```
